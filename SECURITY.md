# Security Policy

## Project status and scope

AG AdliAkademi is an open-source project under active development for education, controlled practice, and community testing. It is not currently represented as a production-hardened or certified digital forensics product.

This policy covers security issues in this repository and the application code maintained here.

## Reporting a vulnerability

**Do not report suspected security vulnerabilities through public GitHub Issues, pull requests, social media comments, or public posts.**

Use GitHub's **Private vulnerability reporting** feature for this repository, if enabled:

1. Open the repository on GitHub.
2. Go to the **Security** tab.
3. Select **Report a vulnerability**.
4. Provide a concise description and safe reproduction details.

If private vulnerability reporting is unavailable, contact the maintainer through the contact method listed on the maintainer's GitHub profile and ask for a private reporting channel. Do not post exploit details or sensitive data publicly.

## What to include

Where safe and relevant, provide the affected page/component or commit, realistic impact and conditions, minimal reproduction steps using a local instance and synthetic data, sanitized logs/screenshots, and any suggested mitigation.

Never include real user data, private records, credentials, tokens, or evidence from an actual investigation.

## Coordinated disclosure

Allow the maintainer reasonable time to investigate and prepare a fix before public disclosure. Do not access, modify, delete, or extract data belonging to other people while validating a report. Stop testing if you encounter data that is not yours.

The maintainer will acknowledge reports when reasonably possible, assess the issue, and coordinate any fix and disclosure. No fixed response or resolution time is guaranteed.

## Safe harbor for good-faith research

Good-faith testing must be limited to a local copy or another environment for which you have explicit authorization. Do not perform denial-of-service testing, social engineering, destructive testing, persistence, or testing against third-party systems.

This policy does not authorize activity that would otherwise be unlawful or violate another party's rights.

## Supported versions

Only the latest publicly available development version is currently considered for security fixes. This may change as the project matures.
